# 小说续写 Web UI/UX 重设计实施规范

> 版本：v1.0（iter152）
> 设计范围：公共入口与小说续写工作区；不含短剧生产工作台
> Figma：[续写工作台 · Web UIUX 重设计](https://www.figma.com/design/CNm0TWwWMkSHaWLPIqSgZX/%E7%BB%AD%E5%86%99%E5%B7%A5%E4%BD%9C%E5%8F%B0-%C2%B7-Web-UIUX-%E9%87%8D%E8%AE%BE%E8%AE%A1)
> 用途：作为后续 `src/web/templates.py`、`src/web/static.py` 与页面行为重构的设计依据。本文不改变现有 API 与安全边界。

## 1. 设计结论

本轮采用浅色、低饱和、中文优先的创作工作台。页面不再使用大面积墨绿色、酒红色或深色按钮：

- 主操作：浅玉色底、深玉色文字与边框。
- 次操作：纸白底、灰褐边框、深色文字。
- 计费操作：浅杏色底、深色文字、橙褐边框；执行前必须确认。
- 危险操作：浅桃色底、深色文字、砖红边框；执行前必须强确认。
- 页面背景：暖纸白；卡片使用纸白、浅米灰或非常浅的语义底色。
- 深色只用于文字、细边框、小型焦点指示和必要图标，不作为大面积背景。

所有用户可见页面只使用直白中文。路由、组件属性、请求字段、状态枚举和无障碍属性属于开发实现，不得原样显示给用户。

## 2. 目标与非目标

### 2.1 目标

1. 覆盖 5 个公共页面与 10 个小说工作区页面，共 15 个页面。
2. 统一所有按钮、图标按钮、字段、状态标记、阶段卡片、提示消息与确认窗口。
3. 明确加载、空内容、失败、阻断、取消、状态丢失、额度不足和恢复路径。
4. 支持桌面、平板和手机；所有交互控件至少 `44 × 44px`。
5. 保留本地单用户、原文只读、逐次授权、费用可见、错误脱敏和任务可恢复边界。
6. 让前端可按路由和组件分期重构，不要求一次替换全部模板。

### 2.2 非目标

- 不改变小说流水线、任务执行顺序或 API 返回结构。
- 不设计短剧角色、资产、镜头、视频、合成和交付页面。
- 不把真实模型、真实计费或外部服务描述为已验证。
- 不在本轮修改生产页面代码。

## 3. 用户语言规范

### 3.1 基本规则

- 一个词只表达一个意思，优先使用用户动作和结果。
- 标题回答“这是什么”，说明回答“现在怎样”，按钮回答“我要做什么”。
- 错误信息必须包含：发生了什么、已有内容是否保留、下一步可以做什么。
- 状态不依赖颜色、图标、转圈或位置；始终显示中文文字。
- 不展示内部异常、文件系统路径、任务类型、模型名、供应方名、请求体、完整提示词或签名地址。

### 3.2 必须替换的旧词

| 旧词或内部词 | 用户界面用词 | 备注 |
|---|---|---|
| `Mock` / `mock` | 离线模式 | 仅说明当前不会发起真实请求 |
| `Beta` | 体验版 | 不在主导航重复展示 |
| `Lint` | 文字检查 | 章节页标签 |
| `Advisor` | 修改建议 | 章节页标签 |
| `Job` | 任务 | 标题、按钮和提示统一 |
| `Provider` | 连接服务或生成服务 | 仅在必须解释连接时使用 |
| `Workspace` | 作品 | 页面与确认窗口均使用作品名称 |
| `Pipeline` | 准备流程或创作流程 | 不展示内部步骤名 |
| `Preflight` | 开始前检查 | 不显示检查脚本名 |
| `Trace ID` | 问题编号 | 只在确需反馈问题时展示短编号 |
| `127.0.0.1` | 本地运行 | 地址仅保留在开发或诊断页面 |
| `cost / budget` | 预计使用额度 / 可用额度 | 金额与范围必须清楚 |
| `stale` | 内容已更新 / 需要更新 | 说明为什么要重新生成 |
| `lost` | 状态待确认 | 提供刷新或重新检查入口 |
| `low / mid / high` | 快速 / 标准 / 严格 | 内部枚举不得进入选项文字 |
| `CNY` | 人民币额度 | 金额同时使用人民币符号或“元” |
| `token` | 文字用量 | 只在用户确需理解额度时出现 |
| `write-book` | 续写任务 | 不展示命令或任务类型 |
| `partial draft` | 临时草稿 | 说明是否已保存 |
| `result_summary` | 结果摘要 | 技术字段名不进入页面 |
| `Insights` | 创作数据 | 当前接口只提供已保存统计，不生成建议 |
| `cache_read / by model` | 内容复用情况 | 不展示模型维度或内部统计字段 |
| `chapter_XX` | 第 XX 章 | 文件名仅放在默认收起的技术详情 |

允许保留的英文仅限用户确实需要识别的文件扩展名；界面优先写“纯文本文件”“电子书文件”，扩展名放在括号内作为补充。

## 4. 信息架构与导航

### 4.1 公共层

```text
欢迎页
├── 我的作品
│   ├── 打开作品
│   └── 新建作品
├── 创建向导
├── 设置
└── 回收站
```

### 4.2 小说作品层

```text
作品概览
├── 创作工作台（单章引导流程）
├── 批量续写（熟练用户入口）
├── 故事规划
├── 章节
│   ├── 章节详情
│   └── 内容搜索
├── 内容检查
├── 创作数据
└── 任务记录
```

### 4.3 `/workbench` 与 `/continue` 的职责

- `/workbench`：默认入口。面向大多数用户，以“准备设定 → 生成大纲 → 生成细纲 → 撰写正文”四阶段引导创作；检查与保存属于正文阶段内动作。
- `/continue`：高级入口。用于多章连续生成、范围设置、额度确认和批量任务管理。
- 两页不得显示相同的大表单；概览页默认引导到 `/workbench`。

## 5. 全局应用框架

### 5.1 桌面端（`≥ 1200px`）

- 左侧导航宽 `220px`，页面内容区自适应。
- 导航展示当前作品与 10 个小说入口；当前入口用左侧 4px 指示条和加粗文字共同标识。
- 内容区左右边距 `48px`，最大内容宽度约 `1100px`。
- 页面标题区包含：标题、简短说明、当前状态、最多两个主要操作。
- 工作区可使用两列；右列只放上下文、提示、任务状态或危险区。

### 5.2 平板端（`768–1199px`）

- 使用 `72px` 顶部导航。
- 顶部保留“作品、创作、章节、任务、更多”；其余入口放入“更多”。
- 卡片最多两列；编辑器和关键表单保持单列。
- 页面操作不得只出现在悬停菜单。

### 5.3 手机端（`< 768px`）

- 设计基准宽度 `390px`，内容左右边距 `18px`。
- 顶部标题栏 `64px`；底部导航 `72px`，保留“作品、创作、章节、任务”。
- 次级页面使用“返回”图标按钮，并提供中文辅助名称。
- 所有内容单列；表格改为卡片列表；确认窗口改为底部弹层。
- 固定操作区不得遮挡最后一项内容，页面底部预留安全间距。

## 6. 路由级页面规格

### 6.1 页面总表

| 路由 | 页面名称 | 页面主任务 | 默认主操作 |
|---|---|---|---|
| `/` | 欢迎页 | 了解产品并进入作品 | 进入我的作品 |
| `/library` | 作品列表 | 查找、打开或创建作品 | 新建作品 |
| `/wizard` | 创建向导 | 创建小说作品并导入内容 | 下一步 |
| `/settings` | 设置 | 管理运行方式与保存规则 | 保存设置 |
| `/trash` | 回收站 | 恢复或永久删除作品 | 恢复 |
| `/w/:name/` | 作品概览 | 判断作品当前状态和下一步 | 继续创作 |
| `/w/:name/workbench` | 创作工作台 | 完成一次单章续写 | 开始当前阶段 |
| `/w/:name/continue` | 批量续写 | 配置并启动多章续写 | 检查并继续 |
| `/w/:name/plan` | 故事规划 | 查看大纲与决定，编辑章节计划 | 保存章节计划 |
| `/w/:name/chapters` | 章节列表 | 筛选并打开章节 | 打开章节 |
| `/w/:name/search` | 内容搜索 | 跨章节与资料搜索 | 搜索 |
| `/w/:name/chapter/:n` | 章节详情 | 阅读、编辑、检查和保存章节 | 保存 |
| `/w/:name/reviews` | 内容检查 | 查看人物、时间、设定问题 | 查看位置 |
| `/w/:name/insights` | 创作数据 | 查看已保存的费用、复用和检查统计 | 无写入操作 |
| `/w/:name/jobs` | 任务记录 | 查看任务与恢复失败任务 | 查看进度或结果 |

### 6.2 欢迎页 `/`

- 内容：一句价值说明、两项入口、五步流程、安全与费用说明。
- 主操作“进入我的作品”；次操作“新建作品”。
- 不展示状态统计、内部服务状态或技术配置。
- 无作品时仍进入作品列表，由作品列表展示空内容引导。

### 6.3 作品列表 `/library`

- 顶部：页面标题、搜索字段、“新建作品”。
- 卡片：作品名、最近编辑时间、章节数、准备状态、“打开作品”。
- 卡片菜单 v1 只提供“移到回收站”；当前没有重命名接口，不显示“重命名”。不得用无名称的三点图标作为唯一入口。
- 空内容：说明“还没有作品”，提供“新建作品”。
- 加载失败：保留搜索与创建入口，提供“重新加载”。

### 6.4 创建向导 `/wizard`

- 小说先选择“导入已有内容”或“从一句话开始”；短剧分支保持隔离，不进入本规范的后续页面。
- 导入流四步：选择方式 → 作品信息与文件 → 检查资料 → 完成。
- 一句话开书流四步：选择方式 → 作品信息与一句话立意 → 确认扩写设置 → 进入工作台。
- 每一步仅展示当前所需字段；v1 提供“返回作品列表”，但不宣称保存未提交的向导草稿。
- 作品名称标注“必填”，不只显示星号。
- 文件区显示允许类型、大小限制、已选文件名和移除操作。
- 导入失败不保留半创建作品；界面说明失败原因和重新选择方式。
- 一句话开书失败保留当前作品名与立意输入，允许修改后重新提交；成功进入 `/workbench`。
- 开始自动准备前展示：将执行的工作、是否使用真实生成、预计额度、可取消规则。
- 进度页按用户步骤展示，不显示内部流水线名称。

### 6.5 设置 `/settings`

- 分为：运行方式、内容与保存、计费确认、辅助功能。
- 默认只展示安全选项；服务地址、模型名等放入折叠的“高级设置”。
- 凭据零片段回显：读取接口只向 UI 提供“已配置”布尔值与更新时间；输入框始终为空，只允许替换或清除。
- 页面 HTML、脚本初始状态、浏览器存储、日志和错误均不得包含凭据掩码、前后缀、长度或任何秘密片段。
- 保存失败保留用户输入并定位到第一个错误字段。

### 6.6 回收站 `/trash`

- 列表显示作品名、删除日期、自动清理剩余天数。
- 单项操作：“恢复”“永久删除”。
- v1 仅提供单项操作；批量恢复或批量永久删除须等后端契约与选择状态测试齐备后再启用。
- 永久删除窗口必须写出目标名称、不可恢复影响，并要求输入作品名称。

### 6.7 作品概览 `/w/:name/`

- 首屏回答：作品是否可继续、最近发生了什么、下一步是什么。
- 展示章节数、待处理问题、最近保存、下一章准备状态和最近章节。
- 默认主操作“继续创作”进入 `/workbench`。
- 资料过期时显示“内容已更新”，说明哪些结果需要重新生成。

### 6.8 创作工作台 `/w/:name/workbench`

- 固定四阶段，与当前后端事实一致：准备设定、生成大纲、生成细纲、撰写正文。
- “内容检查”和“保存章节”是正文阶段内的结果与保存动作，不伪装成独立后端阶段。
- 阶段状态：未开始、可开始、处理中、已完成、需要更新、需要补充。
- 每张阶段卡只保留一个明确主操作。
- 当前阶段处理中时允许离开页面；说明任务仍会运行并提供“查看任务”。
- 前置内容变化后，下游阶段变为“需要更新”，不自动覆盖旧结果。
- 已保存章节提供“打开章节”；不得继续显示“生成”按钮。
- 展示状态按 `stage / has_kb / has_outline / has_plan / draft_count` 派生；评审结果只影响正文卡内部提示，不新增阶段枚举。

### 6.9 批量续写 `/w/:name/continue`

- 明确标注为高级入口，不作为首次创作默认页。
- 设置：章节数、续写起点、写作方式、评审严格程度、可用额度、超时范围。
- 当前后端没有自由文本“写作要求”参数，v1 不显示该字段；启用前必须补参数语义、持久化、任务注入和测试。
- 主操作“检查并继续”先进行开始前检查，不直接启动。
- 计费确认展示章节数、预计使用额度、取消规则和会被更新的内容。
- 额度不足时不禁用全部页面；提供“调整设置”。

### 6.10 故事规划 `/w/:name/plan`

- 用户标签：章节计划、大纲、创作决定；旧标签“辩论决议”改为“创作决定”。
- 章节计划可进入编辑态并保存到现有章节计划接口；取消编辑不写入。当前编辑器代码位于工作台的细纲预览区，重构时复用其校验和保存逻辑并迁移到本页，不把现有 hook 误认为 `/plan` 已经具备。
- 已有正文时，保存章节计划前必须确认相关章节的检查状态会过期；没有正文时直接保存。
- 全局大纲与创作决定在本页保持只读；需要修改大纲时导航到工作台。
- 本页不提供重新生成；重新生成由工作台或批量续写发起，并单独确认覆盖与费用。
- 冲突或缺失用卡片说明，并定位到对应章节计划或工作台。

### 6.11 章节列表 `/w/:name/chapters`

- 搜索、来源筛选、排序和章节卡片/行。
- 来源筛选文案为“全部、续写章节、原文章节”。
- 原文章节为只读；续写章节可打开编辑。
- 空搜索结果显示当前条件并提供“清除筛选”。

### 6.12 内容搜索 `/w/:name/search`

- 搜索范围：章节、人物、故事资料，可组合筛选。
- 结果显示来源、标题、命中片段和“打开”。
- 命中词使用浅色标记，同时保留完整文字，不只用颜色。
- 输入为空时不发请求；显示近期搜索或搜索提示。

### 6.13 章节详情 `/w/:name/chapter/:n`

- 用户标签：正文、编辑、内容检查、文字检查、文风、修改建议、保存记录。
- 原文只读；续写正文支持编辑和自动保存。
- 自动保存状态显示“正在保存、已保存、没有保存成功”。
- 当前没有章节删除接口，v1 不显示“删除章节”；后端另行提供可恢复删除契约后再启用。
- 离开未保存页面时提供“继续编辑、放弃修改、保存并离开”。

### 6.14 内容检查 `/w/:name/reviews`

- 聚合人物、时间、地点、设定与前后文问题。
- 每项包含：问题标题、直白说明、对应位置、严重程度、处理状态。
- v1 操作只有“查看位置”；当前没有检查项处理写入接口，不显示“标记已处理”。重新检查只有在明确对应现有任务入口时才显示。
- 不向用户展示规则类名、评分器名或原始分析文本。

### 6.15 创作数据 `/w/:name/insights`

- 当前页面是只读统计，分为：各章使用额度、内容复用情况、内容检查分项。
- 数据来自已落盘记录；本页不发起生成，也不提供编辑或“采用建议”。
- 未知费用不得显示为 0；缺少统计时说明“暂无可汇总记录”。
- 不展示模型名、内部文件名、字段名、原始调用日志或推理过程。
- 如果未来新增可编辑创作建议，必须先提供独立读取/保存契约，不得复用当前 `/insights` 统计接口伪造状态。

### 6.16 任务记录 `/w/:name/jobs`

- 筛选：全部、处理中、已完成、需要处理。
- 每项显示用户任务名、状态、最近更新时间和一个主要操作。
- “处理中”允许查看进度与取消；“未完成”允许重新开始；“额度不足”允许调整设置。
- 重新开始若会触发真实生成，必须使用计费按钮并重新展示范围、额度和取消规则；只有确定为离线任务时才可使用普通主按钮。
- 状态丢失时显示“状态待确认”，提供“刷新状态”，不得自动重启。
- 技术详情采用失败关闭白名单，只允许问题编号、用户可理解的阶段、状态和时间；未知字段一律不渲染。
- 技术详情明确禁止 stdout/stderr、绝对路径、请求头、完整提示词、供应方请求/响应和签名地址。

### 6.17 页面异常状态实施矩阵

下表是 v1 的最小闭环；“保留”列约束失败后不得丢失的用户状态。

## 7. 组件规范

### 7.1 设计变量

| 语义 | 视觉 | 建议现有变量映射 |
|---|---|---|
| 页面背景 | 暖纸白 `#FBF7F0` | `color/bg/page`（重构时新增语义变量） |
| 卡片背景 | 纸白 `#FFFEFB` | `color/bg/card`（重构时新增语义变量） |
| 主操作背景 | 浅玉色 `#E6EFE9` | `color/bg/primary-action` |
| 计费背景 | 浅杏色 `#F8E7D3` | `color/bg/paid-action` |
| 危险背景 | 浅桃色 `#F4DCD2` | `color/bg/danger` |
| 正文文字 | 深墨色 `#2A2520` | `color/text/primary` |
| 次要文字 | 灰褐色 `#5C544A` | `color/text/secondary` |
| 焦点 | 中明度玉色 `#3F6B5A`，3px | `color/focus/ring` |

v1 只交付浅色模式。Figma 中保留的深色变量不构成深色模式承诺。

### 7.2 文字按钮 `Button`

属性：`Style × State + Label`。

| Style | 用户用途 | 是否确认 |
|---|---|---|
| `Primary` | 当前页面最重要的非计费动作 | 通常否 |
| `Secondary` | 查看、筛选、保存设置等次操作 | 否 |
| `Ghost` | 取消、返回、低优先级操作 | 否 |
| `Paid` | 会触发真实生成或产生费用的动作 | 必须 |
| `Danger` | 永久删除或不可逆覆盖 | 必须强确认 |

所有样式包含：默认、悬停、聚焦、按下、禁用、处理中。规则：

- 高度至少 `44px`，左右内边距至少 `16px`。
- 一屏原则上只有一个主按钮；确认窗口可同时出现取消与确认。
- 禁用按钮旁必须说明原因，不能只变灰。
- 处理中保持原按钮宽度，文字改为“处理中”，并避免重复提交。
- 计费按钮和危险按钮使用浅底深字，不使用大面积深橙或酒红。

### 7.3 图标按钮 `Icon Button`

属性：`Style × State + Icon`；类型为常用、主要、危险。

- 固定 `44 × 44px`，图标建议 `20px`。
- 必须提供中文辅助名称，如“更多操作”“关闭窗口”“刷新状态”。
- 不熟悉的动作同时显示文字提示；移动端重要动作直接使用文字按钮。
- 危险图标按钮只用于移除单个可恢复项；永久删除使用文字按钮。

### 7.4 状态标记 `Status Badge`

| 内部状态 | 用户文字 |
|---|---|
| `offline` | 离线 |
| `not_started` | 未开始 |
| `ready` | 可开始 |
| `pending` | 等待中 |
| `running` | 处理中 |
| `succeeded` | 已完成 |
| `warning` | 请留意 |
| `stale` | 内容已更新 |
| `blocked` | 需要补充 |
| `failed` | 未完成 |
| `aborted` | 已取消 |
| `lost` | 状态待确认 |
| `budget_exceeded` | 额度不足 |
| 其它未知值 | 状态待确认 |

Figma 可继续使用 `Queued`、`Cancelled` 作为组件设计属性，但 API 归一化层必须把真实 `pending` 映射为等待中、`aborted` 映射为已取消；不得把真实值落入未知状态。

### 7.5 表单字段 `Field`

类型：输入、搜索、选择、长文本；状态：默认、聚焦、错误、禁用。

- 标签始终位于字段上方。
- 必填写“必填”，不只用星号。
- 错误边框之外必须显示可操作的中文说明。
- 禁用字段同时说明原因；只读字段仍可选择复制。
- 搜索回车与“搜索”按钮行为一致。

### 7.6 阶段卡片 `Stage Card`

状态：未开始、可开始、处理中、已完成、需要更新、需要补充。“离线”只描述运行方式，不得代替“未开始”。

- 卡片包含阶段名、状态标记、结果说明和一个主要操作。
- “已完成”操作为查看结果；“需要更新”操作为重新生成；“需要补充”操作定位缺失内容。
- 状态改变不得造成卡片大幅跳动。

## 8. 异步任务与反馈

### 8.1 状态机

```text
可开始 → 等待中（API: pending）→ 处理中 → 已完成
                    ├→ 未完成 → 重新开始
                    ├→ 已取消（API: aborted）→ 保留已完成内容
                    ├→ 额度不足 → 调整设置
                    └→ 状态待确认 → 刷新状态
```

- 浏览器轮询只更新对应任务卡和相关阶段，不整页闪烁。
- 页面离开不等于取消；离开前说明任务会继续。
- 取消只停止尚未完成的工作，不承诺回滚已写入内容。
- 重试必须由用户触发；状态丢失、超时或未知错误不得自动重复计费请求。

### 8.2 提示消息

- 成功：“章节已保存。”
- 提醒：“故事资料有更新，建议重新检查。”
- 失败：“没有保存成功，输入内容已保留，请重新尝试。”
- 普通提示 4–6 秒后消失；失败提示保留到用户关闭或完成恢复。
- 提示区使用礼貌播报；高频进度更新不得反复打断读屏。

### 8.3 页面级状态

每个数据页面必须实现：首次加载、局部加载、空内容、失败、无权限/不适用、状态待确认。

- 页面不存在：返回作品或作品列表。
- 小说页面打开短剧作品：进入失败关闭的不适用屏障，说明“当前作品未开启小说续写”，只保留适用入口。
- 确认类型不匹配后，隐藏全部小说写操作，停止小说域读取与任务轮询，不发送保存、生成、删除或取消请求。
- 作品不存在：不回显原始路径或未过滤名称。
- 接口 400：转译为字段或操作说明。
- 接口 409：说明作品正被其它任务使用，提供“查看任务”。
- 接口 500：展示通用失败和问题编号，隐藏异常详情。

## 9. 确认窗口

### 9.1 计费确认

必须显示：

1. 将执行的用户任务。
2. 章节数量或内容范围。
3. 预计使用额度或上限。
4. 何时可以取消。
5. 已完成内容是否保留。

按钮：“取消”“确认开始”。只有“确认开始”使用计费样式。

### 9.2 危险确认

- 标题必须包含动作，如“永久删除作品”。
- 正文写出目标作品名与不可恢复影响。
- 永久删除作品要求输入作品名称；覆盖规划至少要求勾选确认。
- 按钮：“取消”“永久删除”。
- 取消后焦点回到原按钮；确认完成后焦点进入结果标题。

### 9.3 未保存离开

提供三个动作：“继续编辑”“放弃修改”“保存并离开”。关闭窗口等同“继续编辑”。运行中任务使用另一套文案，不与未保存修改混淆。

## 10. 无障碍与键盘

- 正文与背景对比度达到 `4.5:1`；大号文字达到 `3:1`。
- 焦点环 `3px`，与组件边缘保持可见间隔；不得只改变颜色深浅。
- 所有交互目标至少 `44 × 44px`。
- 弹窗打开后焦点进入标题或首个字段；焦点限制在窗口内；关闭后回到触发按钮。
- 标签页使用方向键切换；回车或空格激活。
- 图标按钮必须有中文可访问名称和鼠标提示。
- 错误摘要链接到第一个错误字段；字段同时使用文字说明和语义属性。
- 动画遵循减少动态效果偏好；处理状态可用静态文字替代旋转动画。

## 11. 隐私、安全与费用边界

- 原文只读：UI 不提供修改或覆盖原文章节的操作。
- 本地优先：用户内容默认保存在当前作品目录，不描述为云端同步。
- 真实生成逐次确认：设计不允许“记住本次确认后全部自动执行”。
- 凭据不回显：设置页不显示已保存凭据全文。
- 错误脱敏：不显示绝对路径、堆栈、请求头、完整提示词、供应方响应或签名地址。
- 任务可追踪：计费操作必须进入任务记录，显示用户可理解的名称、状态、时间和恢复动作。
- 状态不确定时失败关闭：显示“状态待确认”，先查询状态，不自动重试。

## 13. DOM 与前端重构约束

### 13.1 保留的行为钩子

重构时可调整结构和类名，但必须保留或显式迁移以下行为：

- 侧栏开关、页面操作菜单和遮罩关闭。
- `data-leave-guard` 离开保护。
- 标签页与当前面板的关联。
- 任务轮询、取消和恢复。
- 表单重复提交防护。
- 提示消息的礼貌播报区域。

建议从“样式类驱动行为”迁移为 `data-ui-*` 行为钩子，组件样式不参与脚本选择器。

### 13.2 建议目录

```text
src/web/
├── components/
│   ├── button
│   ├── icon-button
│   ├── status-badge
│   ├── field
│   ├── stage-card
│   ├── dialog
│   └── app-navigation
├── views/
│   └── <route modules>
├── state/
│   ├── jobs
│   ├── errors
│   └── copy-map
└── static/
    ├── tokens.css
    ├── components.css
    └── views.css
```

当前项目仍使用 Python 字符串模板；上面的目录是职责拆分建议，不要求引入 React、Vue 或新的构建工具。

## 14. 分期重构建议

### 阶段 A：设计变量与文案层

1. 提取颜色、间距、圆角、阴影、字号变量。
2. 建立用户文案映射，先替换 `Beta`、`Lint`、`Advisor`、`Mock`、原始错误和内部状态。
3. 不改变 API 与页面结构。

### 阶段 B：共享组件

1. 按钮与图标按钮。
2. 状态标记、提示消息和确认窗口。
3. 表单字段、阶段卡片和导航。
4. 为组件增加键盘、焦点和辅助名称测试。

### 阶段 C：公共页面

依次重构欢迎页、作品列表、创建向导、设置、回收站；先闭合建书与恢复流程。

### 阶段 D：单章续写主流程

依次重构作品概览、创作工作台、章节列表、章节详情、任务记录；确保任务离页继续和未保存离开保护。

### 阶段 E：高级与辅助页面

重构批量续写、故事规划、内容搜索、内容检查、创作数据；最后移除旧样式和兼容选择器。

每个阶段都需在桌面、平板和 `390px` 手机执行真实浏览器验证；API 单测不能代替界面验证。

## 15. 验收清单

### 页面覆盖

- [ ] 15 个路由均有加载、空内容、失败和恢复设计。
- [ ] 小说页面与短剧作品不匹配时有中文说明和正确返回入口。
- [ ] `/workbench` 与 `/continue` 角色清晰且不重复。

### 视觉与文案

- [ ] 不出现大面积深绿、酒红或纯黑背景。
- [ ] 主、计费、危险按钮均使用浅底深字。
- [ ] 用户页面不出现不必要的英文、内部枚举或技术名词。
- [ ] `Lint`、`Advisor`、`Beta`、`Mock`、`Job` 等旧词完成替换。

### 交互

- [ ] 所有控件目标至少 `44 × 44px`。
- [ ] 计费和危险动作完成对应确认。
- [ ] 处理中防重复提交，离页不隐式取消。
- [ ] 失败保留输入并给出一个明确恢复动作。
- [ ] 状态丢失不自动重试真实请求。

### 无障碍与响应式

- [ ] 键盘可完成核心流程，焦点顺序与返回正确。
- [ ] 状态不只依赖颜色或图标。
- [ ] 桌面、平板、手机无横向溢出或内容遮挡。
- [ ] 减少动态效果模式下仍能理解处理状态。

### 安全边界

- [ ] 不回显凭据、绝对路径、原始异常、完整提示词或供应方响应。
- [ ] 原文章节保持只读。
- [ ] 所有真实生成继续逐次授权并进入任务记录。
- [ ] mock/offline 验收不宣称真实服务已验证。
